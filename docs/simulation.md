# Advisory simulation models

Both the settings preview and runtime use `lib/optimization/simulator.js`. The browser copy is generated by `scripts/sync-source-status.js`; tests compare its bytes and execute the same fixtures in Node and a browser-like VM. `advanced-simulator.js` is a compatibility entry point into that engine.

## Inputs and limits

- Quarter energy is interpreted over 0.25 hours. Estimated load without historical ESS dispatch is `max(0, (gridWh + essWh) / 250)` kW, using the existing positive-ESS-charging sign convention. This approximation does not separate gross import/export or reconstruct the original dispatch policy.
- Inputs are sorted by timestamp. Timestamps must be nonnegative safe integers aligned to 900,000 milliseconds. Duplicate timestamps invalidate every copy. Grid/ESS energies must be finite; coverage must be 720,000–900,000 milliseconds. These thresholds are advisory input rules, not meter certification.
- `coverage.expectedSlots` spans the first through last aligned timestamps, inclusive. `missingSlots` counts quarters in that span without an accepted observation; `excludedSlots` counts rejected input records. Coverage divides valid observations by the greater of the expected span or input record count, so duplicates cannot increase coverage. Missing time outside the supplied span cannot be inferred by this model; the tariff estimator separately reports calendar-month coverage.
- All replay paths require at least **eight valid quarters** and `minCoverageFraction` (default **0.8**) for an illustrative status. Failed coverage returns `insufficient-data`; the settings page clears prior rows, and comparison results have no `bestIllustrative`. Individual replay methods still expose numeric diagnostics with their insufficient status; callers must check it before presenting a scenario.
- Configuration permits at most **200 values per axis**, **1,000 scenarios** and **3,072 input quarters**. Cap/reserve steps must be at least 0.001. Invalid ranges throw before scenario loops and are not silently truncated. Shared indexed ranges avoid tiny-step or floating-point-loop hangs.

Comparison candidates contain summaries rather than a full copy of simulated history for every candidate. Direct `replayWithRecharge` retains simulated quarter records for the demand-tariff comparison.

## Models and assumptions

`simulate` is **conservative-no-recharge**. `compareScenarios` and `replayWithRecharge` enable **explicit-surplus-recharge**, with no inferred recharge when explicit inputs are absent. Without surplus/prices, both use identical battery arithmetic and candidate ordering. The recommendation layer then selects feasible low-cap scenarios, favouring higher reserves; its ranking serves a different purpose from the preview's peak/wear ordering. Neither ranking is a verified financial optimum.

Replay uses one fixed capacity and power-limit set, symmetric charge/discharge efficiency derived from the square root of the configured round-trip efficiency, and a linear wear assumption. It begins at the configured SoC, even if below the reserve: a higher reserve prevents discharge but does not fabricate energy. Recharge is bounded by supplied unused energy, charging power and remaining capacity. PV production alone does not prove unused surplus and is never used to infer it.

Fresh BMS values may override manual capacity/SoC and tighten charge/discharge limits and the reserve floor when automatic values are enabled. The browser and runtime call the same helper and source-status rules; stale/failed telemetry falls back to manual inputs and failed fields are excluded. A current BMS SoC or limit is an assumption applied to a historical replay, not evidence of the battery's state at that historical time. Neither temperature calibration nor future availability is inferred.

`assumptions` records starting SoC, capacity, backup/scenario reserves, charge/discharge limits, efficiency, coverage requirements, and whether surplus or prices were supplied. Settings display the model, effective starting inputs, reserves and coverage alongside the explicit absence of recharge/prices. Runtime recommendations carry the same assumptions and coverage, including insufficient-data results.

## Advanced inputs and cost boundary

The developer-only advanced preview accepts `surplusKWh` and `pricesSekPerKWh` maps keyed by aligned epoch-millisecond timestamps. Supplied values must be finite; surplus cannot be negative. Missing prices remain unknown, while finite negative prices are allowed. No priced-import total is returned for empty or incompletely priced valid history. Extra timestamped inputs do not manufacture missing history observations.

The settings UI deliberately exposes only conservative replay. Advanced inputs must establish unused surplus explicitly; solar allocation and illustrative efficiency curves remain separate. Import cost alone is not total savings: export payouts, contract/tax/VAT semantics and a comparable baseline remain separate work in issue #10. Tariff comparisons share bounded scenario ranges and replay validation but use their own hourly eligibility and calendar-month coverage.

These are historical, advisory scenarios. Missing intervals do not recharge or reset the battery, and their unknown load is not simulated. Passing an 80% threshold does not establish what happened in those gaps. No battery, charger or Nibe commands are sent; learning mode and native device protections remain unchanged.
